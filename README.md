# 星穹铁道 · 回合数/行动值监控提醒

监控游戏左侧行动序列列中的倒计时条（沙漏 + 回合数 + 行动值），当 **回合数 == 0 且 行动值 < 30** 时弹出醒目提醒窗口并响铃。

## 运行环境与依赖

**系统要求**：Windows 10 / 11。首次启动会自动申请管理员权限（弹 UAC 确认即可，与游戏同权限窗口捕获才可靠）。

**需要提前安装（唯一）**：

- **Python 3.10+**（安装时勾选 "Add Python to PATH"）。`start.bat` 会用它创建虚拟环境并自动安装其余一切。

**首次运行自动安装（联网）**：

- Python 依赖：`pillow / numpy / pytesseract / winocr / opencv-python-headless / comtypes / scipy`（即 `requirements.txt`，走阿里云镜像）
- Tesseract OCR 引擎：自动下载（约 50MB，代理 `127.0.0.1:7890` 优先）并安装到 `%LOCALAPPDATA%\Programs\Tesseract-OCR`；静默安装失败时自动尝试 7-Zip 解包兜底

**仓库自带（无需安装）**：

- `templates/digits/`：0-9 数字模板，模板匹配识别的核心，**不可删除**（缺失时自动回退 Tesseract）

**可选组件**：

- `rapidocr-onnxruntime`：RapidOCR 复核功能（config.json 中 `rapid_recheck: true` 启用；默认关闭，不安装不影响使用）
- 7-Zip（`C:\Program Files\7-Zip\7z.exe`）：Tesseract 安装失败时的自动兜底

**运行时自动生成（无需手动创建）**：

- `venv/`（虚拟环境）、`config.json`（默认配置，程序内修改自动保存）、`logs/`（识别历史 CSV + 画面存档 + GUI 日志）

## 主要特性

- **模板匹配识别**：OpenCV 模板匹配（0-9 模板）识别行动值/回合数，抗像素级缺陷——历史上 Tesseract 把 77 读成 7 的丢位问题已根治
- **窗口直捕**：PrintWindow 直接捕获游戏窗口（与 OBS 同机制），游戏窗口在屏幕上可见即可——不需要游戏在前台/聚焦
- **动态定位**：倒计时条随角色行动在列内上下浮动，每帧自动重新定位（六角图标锚点）
- **双样式支持**：金色/红色两种敌人状态（六角图标颜色驱动同色掩码）
- **完整性校验闸门**：数值范围、同回合递减、骤降（多位数→个位数）、归零回弹、低位拒绝、突变三帧确认（含抖动容差）、兜底重置等一套闸门，离谱结果直接丢弃，宁可不识别不误报
- **自动提权**：start.bat 启动时自动申请管理员权限
- **识别日志**：`logs/history_日期.csv`（时间/回合数/行动值/提醒/说明），值变化或提醒时存档画面到 `logs/frames/`（自动保留最近 500 张），GUI 滚动日志同步落盘 `logs/gui_日期.log`；日志采用门控模式——数值变化才记录轨迹，未识别同一原因 5 秒内不重复刷屏
- **双按钮提醒**：弹窗可选「本局不再提醒」（新对局自动恢复）或「下次继续提醒」
- **声音触发（可选）**：WASAPI 进程环回监听游戏音频，匹配预设音效模板（如回合结算/行动值归零提示音）触发事件日志——画面识别之外的独立通道（详见下方「声音触发」）
- **对局进度监测**：剑形/Y形/BOSS 三种锚点图标模板匹配定位顶部进度条带，读取进度百分比与关卡（如 1-3 / 2-5），战斗开始/结束自动识别（标题模板），进度写入 `logs/battle_日期.csv`
- **进度单调校验**：战斗内进度只增不减，回退即判定识别错误——保持上次值并红色告警，不污染基线；新对局 5 秒内高位值忽略（结算页残留防御）
- **条件对齐模板匹配**：数字段比模板宽时右对齐比较（吸收 1px 抗锯齿残影），等宽保持左对齐——修复 9 宽体变体误读（61→6）且不扰动 0/8 区分度
- **模板确认制**：新数字/图标模板一律先提取候选彩色原图，肉眼确认后再入库（`scan_progress_templates.py` 离线扫描 + `verify_realcode.py` 全库回归验证）
- **GUI 状态区进度显示**：回合数/行动值/对局进度同一行实时显示；进度值不变时日志不刷屏（仅变化时记录）
- **启动自动监测**：程序启动后自动开始监测（已配置监测区域时），无需手动点开始
- **对局结束温和弹窗提醒**：对局结束后延迟 N 秒（GUI 可配，默认 10）弹蓝色系温和提醒，显示对局结果（成功/失败）、最终进度、最后一次回合行动值；本游戏窗口在前台或系统运行其他常见游戏（进程名列表可配）时不打扰

## 使用步骤

1. 启动游戏，进入战斗界面（倒计时条可见的界面）。
2. 双击 `start.bat` 打开监控程序（若旧版监控窗口还开着，先关掉它）。
3. 确认捕获方式为「**窗口捕获(推荐,后台可用)**」。
4. 确保游戏窗口在屏幕上**可见**（窗口化即可，不必在前台；不要最小化或移出屏幕，否则游戏不渲染画面，任何工具都捕获不到）。
5. 点击 **「选择监测区域」**——程序会抓取游戏窗口画面，在弹出窗口中用鼠标**框选倒计时条所在的整列**：
   - 倒计时条（沙漏+回合数+行动值）在左侧行动序列列中会上下浮动，所以框选时要**上下留足浮动空间**，框满整列高度；
   - 水平方向框住沙漏到行动值条即可。
6. 松手后自动测试识别，日志区应显示「回合数=X 行动值=Y」。
7. 点 **「开始监测」** 即可。游戏窗口在屏幕上（不必前台）即可持续监测。

## 参数说明

- **回合数等于 / 行动值小于**：触发条件（默认 0 / 30）
- **间隔(毫秒)**：识别频率（默认 500）
- **gamma**：画面亮度校正。HDR 下画面过曝发白时调低（如 0.7），过暗调高
- **允许行动值突变(3帧确认)**：突变（行动值突增）需连续 3 帧确认（含 ±2 抖动容差）才接受为新回合重置
- **捕获方式**：窗口捕获（推荐，后台可用）/ 屏幕区域（游戏必须可见，被遮挡会读到别的窗口）

## 常见问题

- **「未找到游戏窗口」**：游戏没启动，或窗口标题关键字（config 中 `window_keyword`，默认"崩坏"）对不上
- **「未定位到倒计时条」**：区域框得不对（应框整列且包含倒计时条活动范围），或当前不在战斗界面
- **窗口捕获黑屏/失败**：游戏被完全遮挡或移出屏幕时不渲染画面，任何工具都捕获不到；请保持窗口可见
- **游戏窗口改了大小**：监测区域是相对窗口的坐标，改窗口大小后需重新框选
- **误报/漏报**：日志中红色=丢弃原因，橙色=突变确认/校准等事件，蓝色=声音事件；结合 `logs/gui_日期.log` 与 CSV 排查。丢弃日志注明「疑似数字切换过渡帧」的是数字切换动画期间的信息丢失（像素级缺位），程序拒绝且不污染基线是预期防御
- **数字模板失效**：游戏分辨率/字体变化后识别变差，重跑 `venv\Scripts\python.exe build_templates.py` 重新采集
- **自检模式**：`venv\Scripts\python.exe starrail_monitor.py --selftest 截图.png`

## 声音触发（可选功能）

在画面识别之外增加一条独立通道：监听游戏进程的音频输出，匹配预设音效模板，触发时记录蓝色事件日志（如"声音: 行动值归零(分数0.85)"）。原理：WASAPI 进程环回（只捕获游戏进程的声音，Win10 19041+）+ 高通滤波 + FFT 互相关匹配。

**首次配置步骤**：

1. 用任意录音工具录制一段**游戏战斗音频**（含目标音效，如行动值归零/回合结算提示音，10-60 秒即可），保存为 wav。
2. 双击 `collect_sounds.bat`，把录音 wav 拖到窗口上回车——程序自动切分候选音效片段并逐个播放，输入名称（如 `action_zero`）保存。
3. 保存后模板在 `templates/sounds/<名称>.wav`。启动监控程序，勾选界面上的「声音触发(需音效样本)」再开始监测。
4. 若监听不工作，先双击 `capture_test.bat` 自测捕获（游戏开声时运行，输出 `capture_test.wav` 试听确认能录到游戏声音）。

**参数**：`config.json` 中 `sound_threshold`（默认 0.13，越低越灵敏）、`game_process`（默认 StarRail.exe，进程名不匹配时改这里）。

## 对局进度监测

主程序监测对局进度（战斗开始/结束 + 进度百分比 + 关卡），数据写入 `logs/battle_日期.csv`（开始/结束时间、结果、最终进度、时长）。config 中 `battle_progress: true` 启用（默认开，需 `templates/battle/` 模板完整）。

**条带定位**：顶部进度条带通过锚点图标模板匹配定位（`find_band`，三级兜底：`sword.png` 剑形 → `yicon.png` Y形 → `bossicon.png` 翼状菱形）。三种锚点在不同界面形态下二选一出现（普通战/旧UI/BOSS战），位置一致（右缘对齐），匹配阈值 0.75（UI 虚化过渡帧分数 0.5-0.7 会被拒绝丢弃）。

**进度识别**：锚点右缘 +42px 起提取数字区（避开关卡文本如 1-3/2-5），掩码 >180 提取数字组件，像素差模板匹配（阈值 <45 且与次优差距 ≥0.85 倍）+ 条件对齐（段比模板宽时右对齐，吸收 1px 抗锯齿残影）；连续前缀从左到右，% 符号天然不匹配中断；断裂数字拒绝识别保持上次值（不 OCR 兜底，避免 0→1 类误读）。

**单调校验**：战斗内进度只增不减——回退判定识别错误，保持上次值并红色告警；新对局 5 秒内高位值忽略（结算页过渡残留）；`_progress_warn` 每次刷新清除，避免告警残留重放。

**模板维护**：数字/图标模板变更一律走确认制——`scan_progress_templates.py` 离线扫描候选帧 → 提取候选彩色原图编号展示 → 肉眼确认标签 → 按确认结果入库（如 `5_5.png`）→ `verify_realcode.py` 全库回归（保存前后对比，仅目标帧变化才提交）。新变体入库前检查与 0-9 其他模板的平均差均 >45（防止误配）。

## 配置文件说明

`config.json` 首次运行自动生成（程序内修改自动保存）。各配置项含义：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `capture_mode` | `window` | 捕获方式：`window`=窗口直捕（推荐，后台可用）/ `screen`=屏幕区域（游戏须可见） |
| `win_region` | `null` | 窗口内监测区域 `[x1,y1,x2,y2]`（「选择监测区域」时自动保存） |
| `region` | `null` | 屏幕坐标监测区域（screen 模式用） |
| `turn_threshold` | `0` | 提醒触发条件：回合数等于该值时进入判断 |
| `action_threshold` | `30` | 提醒触发条件：行动值小于该值时提醒 |
| `interval_ms` | `300` | 识别间隔（毫秒） |
| `sound` | `true` | 提醒时是否蜂鸣 |
| `foreground_only` | `false` | 仅游戏窗口在前台时监测（screen 模式） |
| `window_keyword` | `崩坏` | 游戏窗口标题关键字（定位窗口/前台判断用） |
| `confirm_ticks` | `2` | 突变需连续确认的帧数 |
| `cooldown_s` | `10` | 提醒冷却（秒） |
| `gamma` | `1.0` | 画面亮度校正（HDR 过曝调低如 0.7，过暗调高） |
| `save_frames` | `true` | 数字变化/提醒时保存识别画面到 `logs/frames/` |
| `max_frames` | `0` | 画面存档上限（0=无上限全量存档，供调试/模板采集；>0 时超出自动删最旧） |
| `log_history` | `true` | 记录识别历史 CSV（`logs/history_日期.csv`） |
| `max_turn` | `99` | 回合数合理上限（超出判定识别错误丢弃） |
| `max_action` | `100` | 行动值合理上限（超出判定识别错误丢弃） |
| `allow_action_reset` | `true` | 允许行动值突变（三帧确认后接受为新回合重置） |
| `reset_turn_min` | `1` | 突变允许的回合数下限（回合数>0 才允许） |
| `reset_action_min` | `1` | 突变允许的行动值下限（行动值>0 才允许） |
| `action_drop_max` | `20` | 同回合一帧内最大允许降幅（超过判定丢位误读丢弃） |
| `rapid_recheck` | `false` | RapidOCR 低频复核（默认关：本地推理与游戏抢 CPU 会卡） |
| `rapid_baseline_s` | `6` | RapidOCR 周期基线校准间隔（秒） |
| `sound_trigger` | `false` | 声音触发（WASAPI 进程环回，需 `templates/sounds/` 有音效样本） |
| `sound_threshold` | `0.13` | 音效匹配触发阈值（越低越灵敏） |
| `game_process` | `StarRail.exe` | 游戏进程名（声音捕获目标） |
| `battle_progress` | `true` | 对局进度/开始结束监测开关（需 `templates/battle/` 模板） |
| `battle_interval_s` | `1.0` | 对局进度检测间隔（秒） |
| `battle_end_notify` | `true` | 对局结束弹窗提醒开关（GUI 可勾选，即时保存） |
| `battle_end_notify_delay` | `10` | 对局结束后延迟弹窗秒数（避开结算动画，GUI 可调 0-300） |
| `other_game_processes` | 常见游戏列表 | 其他游戏进程名数组：系统运行任一进程时跳过对局结束弹窗（可自行增删） |

## 已知限制

- 回合数字按游戏当前渲染的**黄色**识别（红色样式同样支持）；若版本更新后颜色变化，准确性会下降
- 首次使用务必先「测试识别」确认读数正确，再开始监测
- 模板匹配依赖固定字体；游戏更新改字体后需重新采集模板
